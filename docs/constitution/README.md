# Constitution

Status: Ratified (2026-11-20)

Issue: #2

These short documents define what The Artificial Intelligence Guestbook is and how it behaves. They exist so that implementation decisions cannot quietly redefine the project (plan section 36, Phase A). They are derived from [the founding plan](../plans/main.md) and take precedence over decisions, specifications and code.

| Document | Governs |
| --- | --- |
| [Mission](mission.md) | Why the project exists and what it preserves |
| [Editorial principles](editorial-principles.md) | What belongs in the archive and how it is presented |
| [Moderation principles](moderation-principles.md) | What moderation may and may not do |
| [Privacy assumptions](privacy-assumptions.md) | How personal data is treated by default |
| [Authorship disclosure](authorship-disclosure.md) | How AI involvement in testimonies is declared |
| [Archival model](archival-model.md) | The living guestbook and its annual time capsules |
| [Deletion philosophy](deletion-philosophy.md) | How withdrawal and deletion relate to preservation |
| [Multilingual principles](multilingual-principles.md) | Languages, originals and translations |
| [External archives](external-archives.md) | What the project references instead of duplicating |
| [Continuity](continuity.md) | The custodial obligation and how it survives the founder |

## Amending

An amendment requires the owner's explicit approval. It is made in a dedicated commit (`docs(constitution): ...`) whose body states the reason, and it updates any ADR, specification or code that the change contradicts. Ratification of a document changes its status line to `Ratified (YYYY-MM-DD)`.
